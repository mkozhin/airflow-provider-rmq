# Два потребительских цикла написаны дважды, вместе с границей отмены

**Симптом.** Тела `_consume_subscription` и `_consume_fire_queue`
(`airflow_provider_rmq/watcher/consumer.py`) — один и тот же цикл: `while True`
→ статус `connecting` → канал под `call_with_timeout` → passive declare →
consumer-тег с nonce → `_attached(...)` → статус `listening` → метрика →
`async for` с внутренним перехватом, поднимающим флаг доставки → внешний
перехват, вызывающий `_raised_while_cancelling` и перевыбрасывающий
`CancelledError` → `finally` со сбросом состояния и закрытием канала → пауза
перед повторным подключением → четыре одинаковые ветки `except`, различающиеся
только текстом лога.

Реально различаются четыре вещи: откуда берётся соединение (пул на каждый
проход против объекта, выданного при запуске), суффикс тега (`sub_id` против
`fire`), присваивается ли `state.connection`, и какому обработчику уходит
доставка.

**Почему это важно.** Продублирована в том числе граница `delivery_fault` /
`_raised_while_cancelling` — самая тонкая логика в файле: ADR-0007 отводит
отдельный раздел объяснению, почему признак «исключение пришло из обработки
доставки» обязан жить в кадре самого цикла, а не на объекте исключения. Это
знание существует в двух местах, обязанных меняться синхронно. Тест на общий
экземпляр исключения есть у каждого из двух циклов —
`test_a_fault_of_one_task_does_not_disarm_the_cancellation_of_another`
(`tests/watcher/test_consumer.py:1268`) у подписочного и
`..._of_the_fire_consumer` (`:2795`) у fire-цикла, — и каждый держит свой цикл на
месте. Но друг о друге они не знают: правка, внесённая в один цикл и не
внесённая в другой, оставляет оба теста зелёными, и расхождение двух копий
ничем не ловится. Ловит его только отсутствие второй копии.

**Куда копать.** Вынести скелет — `_attach_loop(state, conn_id,
get_connection, queue_name, tag_suffix, handle, label)`, где `get_connection` —
вызываемый объект (поиск в пуле против фиксированного объекта), `handle` —
корутина обработки доставки, `label` даёт субъект для логов. Перестройка
касается кода, который держит корректность отмены, поэтому её стоит делать
отдельным заходом с собственным ревью, а не попутно.
