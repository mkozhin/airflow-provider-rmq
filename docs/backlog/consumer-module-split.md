# `consumer.py` на 3 900 строк с тестом на 10 000 — пора разделить по уже существующим швам

**Контекст.** `airflow_provider_rmq/watcher/consumer.py` — 3 908 строк, треть
всего кода провайдера; `tests/watcher/test_consumer.py` — 10 066 строк.
Внутри файла давно сложились самостоятельные модули с узкими интерфейсами, и
они уже общаются друг с другом через явные объекты, а не через общее
состояние:

| кусок | что внутри | интерфейс |
|---|---|---|
| писатель статусов | `_StatusWriter`, реестр, `_conn_status_turn`, `_write_conn_*` | `record_if_needed`, `store`, `stored` |
| пул соединений | `_ConnState`, `_connect_pooled`, `_drop_connection`, `_usable`, `_await_connected`, `_new_connection` | `get_or_create`, `drop`, `ready` |
| проверка живости | `_check_liveness` и всё до `_probe_connection`: `_Checked`, `_answering`, `_judge_*`, `_probe_*` | `check(subscriptions) → (restart, recreate)` |
| инфраструктура брокера | `_ensure_*`, `_sync_bindings`, provisioning exchange и cooldown | функции над каналом |
| два цикла потребления и обработчики доставок | `_consume_subscription`, `_consume_fire_queue`, `_handle_*`, `_publish_pending` | корутины над state |
| менеджер | `reconcile`, `stop`, `_sync_consumer_tasks`, `_sync_fire_consumer` | публичный класс |

**Почему это стоит записать.** Не ради красоты. Три практических следствия
размера:

- ревью любого изменения в файле требует держать в голове все шесть кусков,
  и девять раундов ревью последнего плана показали, что находки лежат на
  стыках: статусы против живости, живость против пула;
- [[duplicated-consumer-loops]] — вынос скелета цикла — упирается в то, что
  цикл, обработчики и граница отмены живут вперемешку с менеджером; в
  отдельном модуле `delivery.py` это одна функция;
- тестовый файл на 10 000 строк импортирует приватные имена напрямую, и любое
  перемещение ломает сотни импортов — чем дольше ждать, тем дороже.

**Чего не хватает для решения.** Понимания, будет ли `consumer.py` меняться
дальше. Если после текущего релиза модуль замирает, разделение — чистая
переделка без выгоды. Если впереди лидер-лок, cooldown-диагностика
([[cooldown-dag-never-serialized-invisible]]) и вынос цикла, разделение стоит
сделать первым, отдельным коммитом без изменения поведения: перенос с
реэкспортом старых имён из `consumer.py`, чтобы тесты остались зелёными, и
затем перенос тестов по модулям. Разбивать вместе с
[[duplicated-consumer-loops]], в один заход с собственным ревью.
