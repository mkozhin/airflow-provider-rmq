# Умерший watcher-процесс не перезапускается, и на проде этого никто не увидит

Watcher — дочерний процесс шедулера (`_spawn_child`, `listener.py:557`). Процесс, умерший
сам (OOM, segfault, SIGKILL), не перезапускается до рестарта шедулера: в процессе шедулера
нет ни потока, ни обработчика SIGCHLD, которые заметили бы его смерть (ADR 0008, раздел
«Перезапуска нет, живость показывает метрика»). Подписки при этом перестают читаться,
DAG'и по ним не запускаются, а строки `consumer_status` остаются в последнем записанном
состоянии — обычно `listening`.

Единственный сигнал по ADR — отсутствие прироста StatsD-счётчика
`rmq_watcher.cycle_completed`, и правило на него каждая установка настраивает сама. На
2026-11-17 на проде такого сигнала нет: в Prometheus стека наблюдения нет ни одной метрики
Airflow, хосты `airflow` и `rmq` данных в стек не отдают (свежие серии только у `logging`,
`mobile`, `services`). Смерть watcher'а обнаружится по жалобе на незапущенный DAG.

Направления, не исключающие друг друга:

- **Мониторинг.** Довести StatsD Airflow до Prometheus и завести правило «нет прироста
  `cycle_completed` N минут» на каждый шедулер. Кода провайдера не требует.
- **Самовосстановление в провайдере.** Проверять живость ребёнка из шедулера и
  перезапускать его — например, по `Popen.poll()` из хука листенера, который Airflow
  вызывает в процессе шедулера, или из отдельного потока-сторожа. Это пересмотр решения
  ADR 0008, и он должен учитывать петлю падений: ребёнок, умирающий сразу после старта,
  нельзя перезапускать без паузы.
