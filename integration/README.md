# Интеграционные тесты против живого RabbitMQ

Набор разговаривает с настоящим брокером: объявляет очереди, публикует
сообщения, читает их обратно и меряет глубину очереди. Всё остальное
в репозитории — юнит-тесты с моками.

## Почему каталог вне `testpaths`

`testpaths = ["tests"]` в `pyproject.toml` не меняется, а этот каталог лежит
рядом с ним, в корне. Поэтому `pytest` без аргументов и `pytest tests/`
собирают только юнит-набор, и ни один прогон — локальный или в CI — не уходит
на брокер случайно. Живой набор запускается только явным указанием каталога:

```sh
.venv/bin/pytest integration/ -q
```

CI его не гоняет: `.github/workflows/publish.yml` остаётся набором на моках.

## Переменные

Читаются из окружения, а при отсутствии там — из `.env` в корне репозитория.
Разбором занимается сам `conftest.py`: `python-dotenv` в зависимости проекта не
добавляется. Значение из окружения перекрывает значение из файла.

| переменная | смысл |
|---|---|
| `RMQ_TEST_URL` | AMQP-URL брокера вместе с vhost'ом — последним сегментом пути |

`.env` закрыт `.gitignore`: логин и пароль в репозиторий не уезжают.

## Гейт и правила безопасности

Брокер прод-смежный, поэтому правила лежат в фикстурах, а не в договорённостях.

- **Без `RMQ_TEST_URL` набор скипается целиком** — с внятной причиной, а не
  падает. Так `pytest integration/` на машине без брокера остаётся зелёным.
- **Vhost обязателен.** Если в URL vhost не указан или указан `/`, прогон
  прерывается на старте (`pytest.UsageError`), а не скипается: суффиксом имени
  от продовых очередей набор не отгородить, отдельный vhost — единственная
  граница.
- **Уникальный префикс.** Фикстура `scratch` выдаёт имена вида
  `rmqtest.{pid}.{uuid8}.<суффикс>`, и имя без этого префикса она отвергает.
- **Всё созданное удаляется** в teardown той же фикстуры — каждая очередь своим
  каналом, чтобы отказ на одной не отменил удаление остальных. Удаление
  пробуется для каждой очереди, а те, что не удалились, остаются в реестре
  прогона и перечисляются в ошибке: имя — единственный способ найти их в
  прод-смежном vhost'е потом.
- **Никаких policy, настроек уровня узла и `rabbitmqctl`.** Набор работает
  только тем, что доступно по AMQP и Management API в пределах своего vhost'а.
- **Глубина очереди меряется пассивным `queue_declare`** (`scratch.depth`):
  поле `messages` в `/api/queues` отстаёт на интервал сбора статистики и
  утверждение теста не выдерживает.
- **Скипается только этот каталог.** Гейт разбирает список собранных тестов и
  трогает лишь свои, поэтому `pytest tests integration` без брокера скипает
  интеграционные и прогоняет юнит-набор.

## Что нужно на брокере

Отдельный vhost и пользователь с полными правами в его пределах. Права на
продовый vhost этому пользователю не выдаются.

Через Management API (`<vhost>` и `<user>` подставить свои):

```sh
curl -u <admin>:<admin-password> -X PUT https://broker.example/api/vhosts/<vhost>
curl -u <admin>:<admin-password> -X PUT https://broker.example/api/users/<user> \
     -H 'content-type: application/json' \
     -d '{"password":"<password>","tags":""}'
curl -u <admin>:<admin-password> -X PUT https://broker.example/api/permissions/<vhost>/<user> \
     -H 'content-type: application/json' \
     -d '{"configure":".*","write":".*","read":".*"}'
```

Те же три шага на узле брокера — `rabbitmqctl add_vhost <vhost>`,
`rabbitmqctl add_user <user> <password>`,
`rabbitmqctl set_permissions -p <vhost> <user> ".*" ".*" ".*"`. Сам набор
`rabbitmqctl` не зовёт никогда: это разовая подготовка руками.

Проверено на RabbitMQ 4.2.0 / Erlang 27.3.4.5: classic- и quorum-очереди,
topic-обменник, DLX.

## Фикстуры

| фикстура | что даёт |
|---|---|
| `rmq_url` | AMQP-URL брокера после проверки vhost'а |
| `rmq_conn_id` | брокер, опубликованный как Airflow-подключение через `AIRFLOW_CONN_*` — для оператора и сенсора, которые ходят через `RMQHook` |
| `pika_connection`, `pika_channel` | синхронный путь: оператор и сенсор |
| `aio_connection`, `aio_channel` | асинхронный путь: watcher и триггер |
| `rmq_prefix` | префикс этого теста |
| `scratch` | пространство имён прогона: объявление очередей, публикация, глубина, удаление в teardown |
